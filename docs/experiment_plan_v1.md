# LIBERO RGB-D 三维抓取关键区域预测实验方案

版本：v1.0
日期：2026-10-23
状态：待实现、待实验验证。本文的网络结构、超参数和验收阈值是实验起点，不是已获得的结果。

## 1. 实验目标

使用 LIBERO 的专家演示视频及对应深度信息，训练一个网络：**输入当前场景的 RGB-D 图像，输出场景中各物体的抓取关键区域三维点云，允许多个物体、多处区域同时被预测。**

第一版使用视频中的单帧观测训练；完整演示用于提取专家抓取监督。预测时不需要看到未来动作。

| 项目 | 第一版定义 |
|---|---|
| 输入 | 当前时刻的 RGB、深度、相机内外参 |
| 输出 | 场景三维点云，以及每个点的关键区域分数 |
| 学习目标 | 专家成功抓取示范支持的表面区域 |
| 多区域 | 同一物体多个区域可以同时得高分 |
| 多物体 | 同一场景多个物体可以同时得高分 |
| 暂不处理 | 下一步抓哪个物体、夹爪姿态、动作生成、不可见表面补全 |

例如，画面里有杯子和盒子，网络可以同时标出杯柄、杯身侧面和盒子两侧。它预测抓取部位，不决定当前任务先抓谁。

**关键边界：专家没有抓过的位置，不等于物理上不能抓。第一版学习的是示范覆盖的抓取区域，不是所有可行抓法的完整集合。**

## 2. 数据选择和运行环境

使用官方原始 HDF5，保留图像、仿真状态和场景模型。先用 `LIBERO-Object` 跑通，再加入连续操作两个物体的任务。官方任务列表中已有“两种物体放入篮子”等任务。[官方仓库](https://github.com/Lifelong-Robot-Learning/LIBERO)、[任务列表](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/master/libero/libero/benchmark/libero_suite_task_map.py)

不要只下载导出的 MP4。MP4 本身不包含恢复仿真、补充深度和自动提取接触标签所需的全部信息。

建议将数据准备和模型训练分成两个环境：

| 环境 | 用途 | 要求 |
|---|---|---|
| 仿真环境 | 恢复示范、渲染、提取接触 | 按选定 LIBERO 提交的依赖配置，固定版本 |
| 训练环境 | DINO 特征提取、PointNet++ 训练 | PyTorch；核对 PointNet++ 实现与 CUDA 的兼容性 |

LIBERO 官方依赖文件固定了 `robosuite==1.4.0`。不要直接用新版本替换后假定状态恢复和相机接口完全一致。[官方依赖](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/master/requirements.txt)

每次实验记录 LIBERO 提交号、数据版本、物体模型标识、Python/PyTorch/CUDA 版本、PointNet++ 实现版本、DINO 权重标识和随机种子。

## 3. 恢复同步 RGB-D 数据

先检查 10 条示范，通过后再处理全部数据：

1. 根据保存的模型和状态恢复场景。
2. 在同一个恢复状态下重新渲染 RGB、深度、实例分割。
3. 保存相机内参和外参。
4. 检查重建点云、接触位置与图像是否对齐。

RGB 和深度一起重新渲染，避免原始图像与恢复状态存在一帧的时间差。LIBERO 环境提供状态恢复及深度渲染相关接口；下载的数据未必已经保存深度。[环境接口](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/master/libero/libero/envs/env_wrapper.py)、[数据生成脚本](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/master/scripts/create_dataset.py)

| 配置 | 初始设置 |
|---|---|
| 相机 | `agentview`、`robot0_eye_in_hand` |
| 重渲染分辨率 | 两路均为 448 × 448 |
| 深度单位 | 米 |
| 坐标系 | 世界坐标系 |
| 点云范围 | 固定标定的机器人操作工作区 |
| 网络输入点数 | 4,096 |

深度缓冲必须转换成真实距离。手腕相机的外参逐帧更新。使用 robosuite 对应版本的相机工具，并检查 RGB、深度、分割的上下翻转约定。[相机工具代码](https://github.com/ARISE-Initiative/robosuite/blob/v1.4.0/robosuite/utils/camera_utils.py)

像素反投影关系为：

\[
p_{\mathrm{camera}}=d(u,v)K^{-1}[u,v,1]^\top
\]

\[
p_{\mathrm{world}}=R_{cw}p_{\mathrm{camera}}+t_{cw}
\]

其中，深度必须采用与该反投影公式一致的相机轴向深度约定。保存每个三维点对应的相机编号与像素坐标，用来关联视觉特征。

两路点云合并后，在工作区内做空间降采样，去除重复点，再采样 4,096 点。不得根据真实接触标签挑选输入点。若小物体的有效点数不足，统一提高训练和推理的点数，而不是只在训练时围绕标签采点。

**实例分割仅用于离线标签和评估，不作为网络输入，推理时也不要求提供。**

## 4. 提取成功抓取事件

利用演示对应的仿真状态自动制作监督，替代人工在图片中标注关键部位。预测网络仍然只看 RGB-D。

每个抓取事件至少保存：

```text
episode_id         示范编号
object_asset_id    物体模型及尺寸标识
grasp_event_id     抓取事件编号
contact_frame      抓取开始时刻
left_contacts      左手指接触点
right_contacts     右手指接触点
object_pose        对应帧的物体位姿
gripper_pose       对应帧的夹爪位姿
quality_flag       标签质量标记
```

接触点来自手指与物体之间的仿真碰撞记录，不使用夹爪中心代替表面接触。MuJoCo 的接触结构提供接触位置和碰撞几何体标识；需要把几何体映射回手指和物体。[接触数据定义](https://mujoco.readthedocs.io/en/stable/APIreference/APItypes.html#mjcontact)

第一版仅保留刚性物体的夹取搬运事件，初始筛选规则为：

- 两侧手指与同一物体持续接触，初始要求连续至少 3 帧。
- 随后物体被抬起，并与夹爪保持相对稳定。
- 排除仅擦碰、推动物体和开抽屉等事件。
- 同一次持续夹持合并成一个事件，不按夹持帧数重复计数。

抬升距离和相对运动阈值先在抽查事件上确定，并写入配置。保存的离散状态可能漏掉瞬时接触，因此接触不完整或归属不确定的事件标记为低质量，不自动当成负样本。

随机检查 30 个事件：核对被抓物体、左右手指接触、抓取开始时刻及后续搬运。还需检查碰撞表面与视觉表面的偏差；明显落入内部或离开表面的接触不直接用于训练。

## 5. 构建允许多处区域的标签

### 5.1 统一到物体坐标系

将每个接触点转换到物体自身坐标系：

\[
c_{\mathrm{object}}=T_{\mathrm{object}\rightarrow\mathrm{world}}^{-1}c_{\mathrm{world}}
\]

实际实现时对点使用齐次坐标。物体移动、旋转后，同一部位的接触仍能汇总到一起。

### 5.2 汇总不同抓法，不平均位置

对同一个物体模型和尺寸，汇总训练示范中的成功接触区域，保留其并集。

```text
示范 A：抓杯柄 ─┐
示范 B：抓杯身 ─┼→ 标签同时包含杯柄和杯身
示范 C：抓杯柄 ─┘
```

不同物体模型不能直接按坐标叠加。第一版只汇总夹取搬运这一类交互，不将推、拧、拉等不同目标混入同一标签。

一条示范先后抓两个物体，就产生两个物体各自的抓取事件。当前画面同时出现两个有标签的物体时，对两者都生成监督。

### 5.3 逐点软标签

对物体上的可见点计算：

\[
y_i=\max_{c\in C_o}\exp\left(-\frac{\|p_i^{\,o}-c\|^2}{2\sigma_o^2}\right)
\]

- \(C_o\)：该物体的成功抓取接触点集合。
- \(p_i^{\,o}\)：当前可见点在物体坐标系中的位置。
- \(\sigma_o\)：区域宽度，初始取物体包围盒对角线长度的 2%。

靠近任意已示范接触位置，标签就高。取最大值不会把不同抓法平均到物体中央。

| 点的类别 | 监督方式 |
|---|---|
| 有标签物体上的点 | 使用上述软标签 |
| 没有抓取记录的其他物体 | 忽略，不直接标成负样本 |
| 桌面等确定背景 | 负样本 |
| 机器人及归属不明确的点 | 默认忽略 |
| 当前不可见的表面 | 不生成输入点或强行监督 |

已标注物体上远离记录接触的位置会获得低标签。这是示范覆盖目标下的负监督，可能遗漏未展示的有效抓法；模型分数不能解释为抓取成功概率。

## 6. 生成训练样本和划分数据

每个事件先选取接触前约 0.5、1、1.5 秒的 RGB-D 帧，仅保留仍处于该次接近阶段且尚未接触的帧，并补充示范起始帧。这样可以减少网络仅依赖夹爪当前位置的捷径。

每个样本缓存：

```text
xyz            [4096, 3]       世界坐标
dino_feat      [4096, 384]     对应的视觉特征
target         [4096]          软标签
valid_mask     [4096]          是否参与监督
object_ids     [4096]          仅用于监督分组与评估
episode_id                     数据来源
frame_id                       帧号
```

缓存 `object_ids` 不代表将其输入网络。RGB、深度、相机参数及采样索引保留在数据准备产物中，便于回溯。

必须先划分集合，再建立各自的标签库：

| 测试类型 | 划分方式 | 验证内容 |
|---|---|---|
| 已见物体的新场景 | 按整条示范划分，初始比例 70%/15%/15% | 新位置、视角、遮挡 |
| 未见物体实例 | 按物体模型分组划分；同一模型出现的相关数据不得跨组 | 新物体迁移 |

训练标签只汇总训练示范接触；验证和测试使用各自的独立接触记录。不得先汇总全量接触再拆分数据，也不得随机拆分相邻视频帧。

先盘点同类物体的模型数量和抓法分布。只有一个模型的类别不能验证同类新实例泛化；只有一种抓法的物体不能验证多抓法学习。样本不足时增加示范或资产，并明确这是扩展实验。

## 7. 网络结构

采用冻结 DINOv2、PointNet++ 分割骨干及逐点分类头。

```text
两路 RGB → 冻结 DINOv2 → 像素视觉特征
                               │
深度＋相机参数 → 三维点云 ←─────┘
                       ↓
              合并视角、裁剪工作区
                       ↓
             4,096 个点及视觉特征
                       ↓
              PointNet++ 分割骨干
                       ↓
              4,096 个区域分数
```

选择 DINOv2 ViT-S/14，使用 384 维 patch 特征。通过像素位置对 patch 特征图插值，得到每个三维点的视觉特征。不要使用整幅图像的单个全局向量。[DINOv2 官方实现](https://github.com/facebookresearch/dinov2)

设批大小为 B：

| 模块 | 输出尺寸 | 初始配置 |
|---|---|---|
| 特征压缩 | B × 4096 × 64 | Linear 384→64 |
| SA1 | B × 1024 × 128 | 半径 4 cm，最多 32 邻点；MLP 64、64、128 |
| SA2 | B × 256 × 256 | 半径 8 cm，最多 32 邻点；MLP 128、128、256 |
| SA3 | B × 64 × 512 | 半径 16 cm，最多 32 邻点；MLP 256、256、512 |
| FP3 | B × 256 × 256 | 三近邻插值、跳跃连接、MLP 256、256 |
| FP2 | B × 1024 × 128 | 三近邻插值、跳跃连接、MLP 256、128 |
| FP1 | B × 4096 × 128 | 三近邻插值、跳跃连接、MLP 128、128 |
| 分类头 | B × 4096 × 1 | 逐点 MLP 128→64→1 |

SA 表示邻域采样与聚合，FP 表示特征上采样；各级跳跃连接保留对应分辨率的特征。输入坐标与视觉特征分别传入骨干，邻域 MLP 拼接相对坐标。最后一层输出 logits，不加激活；推理时使用 Sigmoid。

保留米制尺度，仅做平移中心化。不要任意缩放场景后继续沿用固定米制邻域半径。

**每个点独立输出区域分数，因此可以同时预测多个高分区域。输出区域不包含左右手指的配对关系，也不等于完整抓取姿态。**

## 8. 损失函数和训练配置

采用带掩码的二元交叉熵。实现时以物体为单位平均，再对物体平均，避免大物体占据全部损失；背景项单独平均。

\[
L_{\mathrm{object}}=\frac{1}{|\mathcal O|}\sum_{o\in\mathcal O}\frac{1}{N_o}\sum_{i\in o}\operatorname{BCEWithLogits}(z_i,y_i)
\]

\[
L=L_{\mathrm{object}}+0.1L_{\mathrm{background}}
\]

仅对有效点计算。不存在背景或有效物体的项跳过，避免除零；无有效监督样本不进入训练。

| 参数 | 初始值 |
|---|---|
| 优化器 | AdamW |
| 学习率 | 1e-4 |
| Weight decay | 1e-4 |
| Batch size | 8，显存不足时减小 |
| 最大 epoch | 100 |
| 提前停止 | 验证指标连续 15 个 epoch 无改善 |
| 随机种子 | 0、1、2 |
| 冻结 | DINOv2 |
| 更新 | 特征压缩层、PointNet++、分类头 |
| 选优指标 | 验证集固定区域预算下的接触覆盖率 |

预先缓存 DINO 特征。第一版增强使用小幅坐标扰动和点丢弃，保持坐标、视觉特征、标签索引一致。若改动图像颜色或裁剪，需要重新计算对应视觉特征和映射。

每个 epoch 记录训练损失、验证覆盖率、有效监督点比例及各物体结果。保存配置、最近一次权重和最佳验证权重。遇到 NaN、标签全零或有效监督点异常减少时停止该轮训练并检查数据。

## 9. 推理接口和输出

```text
当前 RGB-D＋相机参数
    ↓
构建工作区点云及 DINO 特征
    ↓
网络输出逐点分数
    ↓
用验证集选定的阈值筛选
    ↓
导出关键区域点云
```

输出至少包含：

```text
scene_points.ply    所有采样点及分数颜色
key_regions.ply     阈值筛选后的关键点集
scores.npz          原始坐标、分数、采样索引
overlay.png         分数投影到 RGB 的可视化
```

恢复中心化前的世界坐标后导出。阈值只在验证集选择，不能根据测试结果调节。默认保留所有高分点，不强制只保留最大连通区域。

推理不读取仿真接触、专家未来动作、物体真实位姿或实例标签。输出是观测点云的子集，不补出未观测表面。

## 10. 对照实验与评估

### 10.1 三组模型

| 实验 | 网络输入与结构 | 目的 |
|---|---|---|
| A | XYZ＋RGB，PointNet++ | 几何与颜色基线 |
| B | XYZ＋DINO，逐点 MLP | 不聚合三维邻域的基线 |
| C | XYZ＋DINO，PointNet++ | 完整方案 |

各组使用相同数据划分、采样、标签和选优规则。另报告相同区域预算的随机选点基线。

### 10.2 接触覆盖率

主指标：固定预测区域大小时，对独立测试接触点的覆盖率。

例如，对每个测试物体的可见采样点，保留得分最高的 20%，再统计测试接触点中有多少距离该点集不超过容差。初始容差采用与标签区域宽度相同的尺度设置，并在验证阶段固定。

\[
\mathrm{Coverage}@q=\frac{\#\{c\in C_{\mathrm{test,visible}}:\min_{p\in S_q}\|c-p\|\leq\delta\}}{|C_{\mathrm{test,visible}}|}
\]

其中，\(S_q\) 是分数最高的 q 比例可见点，\(\delta\) 是距离容差。按物体与事件汇总，避免长夹持事件重复主导指标。

评估时可以利用实例标签划分物体，但不能将其输入网络。用近似均匀的空间采样降低点密度差异；严格表述为点数预算，不把它直接等同于精确表面积。

同时报告：

- 10%、20%、30% 点数预算下的覆盖率。
- 各物体、各抓取方式的覆盖率。
- 三个随机种子的均值和波动。
- 当前视角下测试接触的可见比例；无可见接触的样本不记为满分。
- 阈值输出占可见物体点的比例，检查是否大面积涂亮。

可见性通过相机投影、深度一致性和物体归属判断。只能评估可见表面时，必须同时报告可见比例。

不能把同一次抓取的左右手指接触区误认为两种抓法。抓法分组依据完整事件的接触分布及相对夹爪姿态，并人工核对代表事件。

不将未标注表面全部视作物理不可抓区域，因此不以“全物体抓取可行性准确率”描述结果。

## 11. 开发顺序和验收

以下文件名是待实现的模块约定，并非已有可运行脚本。

| 顺序 | 模块 | 输出与通过条件 |
|---|---|---|
| 1 | `audit_dataset.py` | 物体、示范、状态字段清单；10 条示范恢复成功 |
| 2 | `render_rgbd.py` | 同步 RGB-D 与相机参数；图像、点云与分割对齐 |
| 3 | `extract_grasps.py` | 抓取事件表；随机抽查 30 个事件，至少 27 个归属及接触正确 |
| 4 | `build_samples.py` | 划分清单、分集合标签库、样本缓存；无跨集合泄漏 |
| 5 | `model.py`、`train.py` | 在 20 个样本上过拟合；关闭增强，确认标签可拟合 |
| 6 | `evaluate.py` | 三组模型、两类划分的覆盖率及可见比例 |
| 7 | `predict.py` | PLY 点云、原始分数和 RGB 热力图 |

抽查阈值是工程准入标准，不是统计意义上的准确率保证；若存在系统性错位，即使达到数量阈值也需要修复。

在正式训练前，必须确认：

1. 接触标签落在正确物体表面。
2. 小样本训练能够拟合标签。
3. 数据确实包含要验证的多处抓取区域。

小样本测试通过不代表泛化成功。正式实验分别回答：新场景是否有效、新实例是否有效、多种示范抓法是否同时保留。效果不足时根据对照实验定位数据覆盖、特征或几何聚合问题。

- 固定的数据划分清单与无泄漏检查记录。
- RGB-D、相机参数、接触标签与样本缓存。
- 网络代码、依赖版本、训练配置及权重。
- 三组模型的逐物体评估表。
- 输入图像、专家接触、预测区域的对照图。
- 多物体、多区域及失败案例的点云可视化。
- 对结果适用范围的说明：示范支持的抓取区域、可见表面、已见或未见物体。

本阶段完成的判据是：能够从 RGB-D 生成可检查的三维区域预测，并用独立示范定量判断区域学习和迁移是否成立；不以已经实现机器人抓取成功作为本阶段结论。
