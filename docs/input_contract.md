# Training input contract

The user's clarified requirement on 2026-10-23 supersedes the single-frame input in the original v1 experiment plan: **one complete expert demonstration video, together with depth at every frame**, is one model input. All saved frames are retained in time order. The pilot uses both `agentview` and `robot0_eye_in_hand` cameras at 448×448, with aligned RGB and metric depth plus per-frame camera calibration. Input data contains no segmentation masks or segmentation IDs.

`src/render_rgbd_episode.py` restores each saved LIBERO simulator state and writes one chunked HDF5 file per demonstration. The file contains `/frame_indices`, and for each camera `/rgb`, `/depth_m`, `/K`, and `/camera_to_world`. The first dimension of image/depth arrays is the full demonstration length. There is no crop, clip, subsampling, or segmentation rendering in this pipeline.

Expert collision contacts and simulator object poses remain separate supervision sources. They must not be mixed into the video/depth model input. Any model architecture must consume the full temporal sequence; the former single-frame PointNet++ input specification requires revision before training. Train/validation/test splits must be at demonstration/asset level to avoid leakage. The full demonstration includes later frames by design, so evaluation must be retrospective full-video grasp-region prediction; it cannot be described as an online early prediction.
